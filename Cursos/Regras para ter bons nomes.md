1. Autodescritivos
2. Evite colocar nomes semelhantes entre elementos
3. Constantes que representam os literais
4. Nomes que confundem com outros nomes
5. Nomes com letras que podem remeter a outras letras. 
6. Evite nomes com significados semelhantes, colocando valores sequencias, diferenciando colocando prefixos como the ou a. 
7. Evite nomes redundantes, por exemplo, uma variável jamais pode ter variável no nome. Uma tabela não pode ter tabela no nome.
8. Coloque nomes pronunciáveis, sem muitas abreviações
9. Evite nomes pequenos. O tamanho do nome deve ser proporcional ao tamanho do escopo.
10. Evite nomes codificados.
11. Nomes de classe não podem ser verbo. Mas sim substantivo.
12. Funções ou métodos devem conter verbos. É interessante colocar prefixos como get, set, is e etc.
13. Evite usar o construtor para instânciar uma classe, mas sim uma função construtora que descreve bem o que está instânciando.
14. Evite jargões ou girias nos nomes.
15. Defina um verbo fixo para cada caso e continue nele. Por exemplo, evite criar funções com nomes como get e fetch, onde get e fetch tem o mesmo sentido,  escolha um verbo e seja feliz com ele.
16. Evite usar verbos iguais para sentidos diferentes. 
17. Selecione nomes técnicos para programadores, não para outras áreas.
18. Adicione contextos as variáveis. Evite colocar nomes que sem contexto não fazem sentido, coloque eles a uma classe, namespace, tipo estruturado, prefixo do nome ou afim para colocar um contexto a variável.
